# Демо: наскрізний прогін на реальних чатах

Знято `scripts/demo.sh` на поточній версії коду, 24.11.2026, на 3 реальних чатах: 1 DM і 2 групи
(`BACKFILL_DAYS=7`, модель `claude-sonnet-5-5`). Назви та ID чатів автоматично замасковані (`scripts/mask_log.py`).

| Лог | Що відбувається | Результат |
|---|---|---|
| [`run1.log`](run1.log) | Перший прогін: історія за 7 днів | 44 повідомлення; 7 днів: 4 відсіяні як шум **без LLM**, 3 → LLM (з них 2 модель позначила `relevant:false`), 1 самарі експортовано |
| [`run2.log`](run2.log) | Одразу повторний прогін | **0 нових, 0 LLM-викликів, 0 нових самарі**; `total = distinct = 44` |
| [`run3.log`](run3.log) | У DM написано 3 нові повідомлення, `--include-today` | Підтягнуто **рівно 3** (курсор DM зсунувся, групи не змінилися); 1 LLM-виклик — лише змінений день; `total = distinct = 47` |
| [`run4.log`](run4.log) | Ще один повторний прогін з `--include-today` | 0 нових, 0 LLM-викликів, дублів немає |
| [`sample_summary.md`](sample_summary.md) | Самарі з `run3`, як воно лежить у markdown-vault | Рішення, action items з власниками і термінами, відкриті питання |
| [`offline_demo.log`](offline_demo.log) | `python3 scripts/demo_offline.py`: фейковий Telegram і фейковий LLM, реальний код ядра | Краш посеред читання → відновлення без пропусків; одночасний запуск → `skipped` |

Як читати лог: `LLM-викликів у цьому прогоні` рахує HTTP-запити до Anthropic. `messages: total=… distinct=…` —
рівність означає, що дублів немає. `cursor` / `stored` — останній `msg_id` і кількість збережених повідомлень по чату.

Відтворити: `bash scripts/demo.sh run1 <id1> <id2> <id3>`, потім `run2` з тими ж ID, потім написати
кілька повідомлень і `run3 <ids> --include-today`.
